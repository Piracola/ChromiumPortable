Helium 是什么

Helium 是 imputnet 维护的 Chromium 分支，出发点是把浏览器里那些「不是为用户服务」的部分去掉：默认拦截广告、移除 Google 遥测与后台上报、砍掉推广位和账号绑定引导，同时保留完整的 Chromium 内核与扩展兼容性。

如果你喜欢 Chrome 的性能和扩展生态，但不想要它绑定的那一整套服务，Helium 是一个合理的落点。本仓库在它之上再叠加 Chrome++ 的便携化能力，让它彻底不碰你的系统。

正式版和预发行版

文件名不带 Preview 的是正式版，日常使用选它。带 Preview 的是上游最新预发行版本，用来提前验证上游改动，稳定性没有保证。

两个包放在同一个 GitHub Release 下。如果某次只有正式版更新、预发行版没动，构建流程会自动把上一版的预发行压缩包保留在新 Release 里，所以你总能在最新一条 Release 里同时拿到两个包。

怎么用

  1. 从 Releases 页面下载需要的压缩包。
  2. 解压到任意位置。
  3. 双击「开始.bat」创建桌面快捷方式，或直接运行 Helium\chrome.exe。
  4. 用户数据与缓存会生成在 Helium\Data 和 Helium\Cache。

怎么更新

关掉浏览器，备份旧版 Helium 文件夹里的 Data 目录，删除旧文件夹，把新版解压到同级目录，再把 Data 放回去。本仓库每天跟进上游，有新版就会自动发布。

校验下载的文件

每个 Release 正文里都列出了压缩包的 SHA256。下载后在 PowerShell 里跑一行命令，把结果和 Release 里的值比对，一致就说明文件和构建产出完全一致，中途没有被替换或损坏。

certutil -hashfile .\Helium_版本号_日期.7z SHA256

构建日志也公开在 GitHub Actions 里，可以核对这个压缩包确实由那一次构建产出。

开箱即用的增强

集成 Bush2021/chrome_plus，以下功能默认启用，都可以在 chrome++.ini 里改或关掉。

  • 用户数据与缓存存放在程序同级的 Data、Cache 文件夹
  • 双击关闭标签页，并保留最后一个标签页
  • 悬停标签栏时用滚轮切换标签页
  • 地址栏内容与书签在新建前台标签页中打开

常见问题

便携版和官方安装版有什么区别？

内核和功能完全一样，都来自官方安装包。区别是便携版不执行安装：不写注册表、不注册后台更新服务，用户数据与缓存保存在程序同级的 Data、Cache 文件夹里。整个目录可以随意搬动或拷进 U 盘，删除文件夹就等于卸载干净。

会自动更新吗？

不会。便携版不注册系统更新服务，所以不会在后台自己升级。本项目每天用 GitHub Actions 检查官方是否发布新版本，有就自动构建并发布到 Releases，你手动下载覆盖即可，更新时保留 Data 目录就能留住全部数据。

怎么确认下载的文件没被篡改？

每个 Release 的正文里都有一张校验表，列出每个压缩包的文件名、体积和 SHA256。下载后在 PowerShell 里执行 certutil -hashfile 文件名.7z SHA256，把输出和表里的值比对一致即可。构建全过程的日志也公开在 Actions 里，可以核对压缩包确实由那次构建产出。

用户数据保存在哪里？换电脑怎么迁移？

保存在浏览器文件夹同级的 Data 目录（缓存在 Cache 目录）。迁移时把整个文件夹拷到新电脑就行，书签、密码、扩展、登录状态都会跟着走，不需要重新配置。

杀毒软件报毒怎么办？

Chrome++ 的便携化依靠把 version.dll 注入到浏览器进程来实现，这属于 DLL 劫持技术，部分安全软件会因此产生启发式误报。本项目的构建脚本、工作流和每次构建的完整日志都在 GitHub 上公开，压缩包由 GitHub Actions 直接产出并附带 SHA256，你可以自行核对来源；介意的话也可以按仓库说明在本地自行构建。

支持 32 位系统吗？支持 Windows 7 吗？

只提供 Windows x64 版本，没有 32 位构建。系统要求跟随上游浏览器本身，当前上游各浏览器均已停止支持 Windows 7 / 8.1，建议在 Windows 10 或 Windows 11 上使用。

可以和已经安装的浏览器同时用吗？

可以。便携版有自己独立的数据目录，和系统里安装的版本互不干扰，两者能同时运行。

这个项目收费或者带广告吗？

不收费也不带任何推广。构建脚本只做解包、集成 Chrome++、注入、压缩四件事，不改主页、不预装扩展、不夹带任何私货，源码遵循 MIT 许可证并全部公开。
